# 真實 API 連線測試紀錄

這些 JSON 是使用本機 `.env` 設定的真實模型 API 所取得的回答與工具軌跡，未使用模擬模型。
紀錄不包含 API 金鑰；有時間戳記的檔案使用 Asia/Taipei 時區。

| 檔案 | 內容 |
|---|---|
| `live-connection.json` | 首次連線：查詢營業時間，模型實際呼叫資訊工具並使用資料庫結果回答。 |
| `live-agent-checks.json` | 第一輪：三杯報價、四杯追問、缺少商品與範圍外問題。範圍外問題當時失敗，原始回答予以保留。 |
| `live-check-summary.json` | 第一輪檢查與人工審查註記；「沒有用工具」不等於「已婉拒範圍外要求」。 |
| `live-scope-retest.json` | 加強範圍規則後，重新測試寫詩、以便利商店為題寫詩、寫程式三類要求。 |
| `live-gradio.json` | 首次透過 Gradio 聊天端點測試。金額正確，但模型把第二件 6 折誤稱半價，附有審查註記。 |
| `live-gradio-final.json` | 補齊工具的優惠名稱、折後單價與原價小計後，再透過 Gradio 測試三杯報價、四杯追問與範圍外問題；逐題結果見 `passed`。 |

本輪修正：

1. `agent.py` 明確限定客服任務，即使創作主題包含便利商店也應婉拒。
2. `store_tools.py` 回傳從資料庫規則計算出的優惠名稱、折後單價、原價小計和袋子單價。
3. `agent.py` 要求逐字引用工具提供的優惠名稱，避免自行改稱半價等其他促銷。
4. 程式測試增加「資料庫優惠改成 50% 時，名稱和四捨五入結果也跟著改變」的驗證。

上表的 `live-*.json` 是針對連線與整合問題的測試，不作為作業要求的 10 題工具選擇分數。
